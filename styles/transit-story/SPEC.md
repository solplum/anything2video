# 线路叙事 · transit-story

**状态：原创、可播放的无声视觉原型；手动接入 kit。** 图解讲解路线中的一种叙事处理，不是 `config.style` 新皮肤，不替换 `line-art`、`math-lab` 或现有图解组件。本整合版本已注册到主目录，原型核心不改动其他风格、共享 Root、配方、稿件确认门或最终验收流程。

## 不只是画出一条线

线路表示进程，站点表示已发生事件，换乘表示依赖会合。先到的一条线会等待；其他必要条件没有满足，出口不会打开，后续站点不会出现。颜色辨识线路，人物/放映/勾选图标补充辨识，不能仅靠颜色表达成败。

本例是虚构放映会：观众准备与场务准备并行，观众先到，会合站等待，场务到齐后道岔转向，才能开场。所有站名、布局、图形、状态规则和动画独立制作，没有搬用上游素材。

- 奶白纸面、橘红和青绿线路、黄色会合站、黑色终点。
- 主路线由横/竖/45°段组成，站点只在实际到达时揭示。
- 会合环的每个分段对应一条真实入站依赖；不把两个条件包装成绩效数字。
- 先补齐会合条件，再开道岔，再走末段，最后揭示终点。
- 横屏和竖屏分别布局；竖屏不是把横屏裁掉或压扁。

## 可复用边界

`scene.mjs` 中：

- `compileTransit(graph)` 编译有向无环事件图。源节点给 `startAt`，边给 `duration`，节点可给 `dwell`。普通节点和会合节点都必须等**全部**入边到达才能放行。
- `transitState(graph, frame, fps)` 是纯函数，可倒序取帧；没有 wall clock、随机源或累计模拟状态。浮点事件时间在编译时规范到纳秒精度，避免精确到站帧晚一帧。
- `blockedAt` 让一条线停在部分进度，且不产生到站事件。暂停不会偷偷变成成功。条件恢复后重新编译图即可，但此原型没有在线状态流或暂停/恢复交互引擎。
- `renderTransit({graph, layout, frame, fps, ...})` 接受自己的事件图、坐标、路线拐点、站名和文案。`story.json` 与两个 `layout.*.json` 提供可编辑输入。图标和色板仍是本例的三种线路语汇，不是任意图标库。
- `TransitStoryFrame` 为薄 React/Remotion 包装；与 HTML 预览、离线实渲调用同一 SVG 核心。

此图引擎表达 **ALL 依赖**，没有 OR / 条件选择 / 带资源的复杂循环。如果故事有回访站点，应把每次事件作为独立节点并明确连接；不能用一个循环掩盖时间逻辑。地图布局需要人为设计，不含自动排版或保证任意长文字不碰撞的引擎。自定义图应同时提供布局，并重新检查文字与线路。

本例 `delay` 与 `blocked` 是测试选项。换自己的图后，以图数据为准，不同时假定示例 `delay` 会改写自定义图。样片 Composition 为 18 秒；把源节点延迟到片长之后时，必须延长工程，不能声称已经展示结局。

## 制作与验收要点

1. 先写每站的事件和边的含义，确认会合是“都必须满足”，再画线路。
2. 先查看正常、延迟、阻塞三个时钟。最后一条线的时间改变时，后续放行与终点必须随之改变。
3. 隐藏叙事文字，仍应看出等待、条件补齐、道岔打开、继续行进。
4. 横/竖屏逐一核对线路、标签和终点；自定义交叉线应明确“穿过”还是“换乘”。本例没有非换乘交叉，不假称已覆盖该图元。
5. 回接原有事实、稿件、声音、动作复核和最终 QC。渲染器用 0 起帧，若登记原合同 1 起含端点动作窗，只转换一次。
