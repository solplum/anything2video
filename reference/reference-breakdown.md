# 参考片拆解：把一段参考动画拆成能写进分镜的数字

> 方法与工具移植自 [huashu-art-motion](https://github.com/alchaincyf/huashu-art-motion)（MIT，
> 原 01 号「拆解」+ `scripts/analyze/breakdown.py`；许可副本
> `LICENSE-THIRDPARTY/MIT-huashu-art-motion.txt`），按本 skill 的证据纪律适配。
> 工具：`scripts/reference_breakdown.py`（一条命令出全部产物，PEP 723 内联依赖，脚本模式运行）。

## 何时用

[调研阶段](production-workflow.md#research)拿到对标参考片时：爆款判例复盘、甲方参考、风格样片对标。
这是 aesthetic-rules P2「参考素材先逐帧拆解成手法清单，再逐镜头判断适配性」的工具化——
style-ledger 里 2026-10-06 敦煌爆款判例当时的拆解是手工做的，本工具把这一步管线化：
1.5 小时的人工量测（接触表、逐帧差、网格拟合、运动热图）一条命令出齐。

## 证据边界（先读）

- 拆解产物是**结构、节奏、手法**的证据，不是制作方式的证据。量出的转场节奏、运动密度、构图可以借；
  参考片的帧不得进成片（[契约素材规则](production-contract.md#assets)），`ref/seg??.png` 只能当图像生成的构图参考输入，
  按 `ai-frame-sop.md` 登记为 reference 来源。
- 观察到「像 AI」只能写推测，不作为官方制作技术或比例的声明（统一合同素材节）。
- `cuts.json` 的网格是**剪辑节拍**拟合，不是音乐 BPM 真值：自己配乐的卡点真值仍走
  `music-beat-sync.md`（librosa 网格＋渲染回测）；两者的分工同 beat-sheet 的双通道分工。

## 一条命令

```sh
uv run scripts/reference_breakdown.py --video 参考.mp4 --out <工程>/research/reference-breakdown/
```

| 产物 | 用途 |
|---|---|
| `sheet_*.jpg` | 4fps 接触表：一眼看出有几段、每段是什么 |
| `diff.npy` | 逐帧平均灰度差，给后续所有工具与并行 agent 共用 |
| `cuts.json` | 转场起点（帧/秒）＋节拍网格拟合（80% 内点下最大步长、残差、BPM 候选） |
| `转场/T??.jpg` | 每个转场起点前 2 帧起、每 2 帧一格的接触表——**转场机制只能从这里看出来** |
| `镜内运动/运动热图.jpg` | 每段静止区间逐像素最大帧差叠加图，标运动面积占比 |
| `关键帧总览.jpg` | 每段一张的构图地图 |
| `ref/seg??.png` | 原分辨率参考帧，喂图像生成当构图参考（登记，不进成片） |

判读阈值：静止段帧差 <2，转场段 10–40；默认 `--thresh 5 --debounce 12`，按片调。

## 五步读法（数字 → 分镜）

1. **物理参数（5 分钟）**：ffprobe 确认分辨率/帧率。参考片 60fps 就按 60fps 拆——帧号是之后
   所有规格的公共语言。
2. **全貌三张图（10 分钟）**：接触表看段落；关键帧总览当后续工作的地图；（可选）`ffmpeg -lavfi
   showspectrumpic` 出参考片频谱图——谐波干净、16kHz 一刀切＝参考片的音乐是代码合成的，
   可作为「它的配乐做法」的结构证据（仍是推测，不当事实声明）。
3. **量转场与节奏（15 分钟）**：`cuts.json` 的转场起点序列如果间隔是常数整数倍，参考片就有节拍
   网格（如起点 = 84 + 14.06·n 帧 ≈ 128 BPM 八分音符）。网格成立时，它的段落时长、转场时长、
   元素入场全部落在网格上——你的 beat-sheet 对标它时按「第几拍」抄节奏，不按裸秒。每个转场看
   60fps 接触表写机制描述（「8 条竖条依次落下回弹」），粗看只会写成「方块转场」。
4. **镜内运动（15 分钟）**：运动热图告诉你每段多少面积在动、哪里在动。huashu 的实测教训：
   以为「每段就是一张画」，热图显示每段 2.5–34% 面积在动——**没做这步就开工，做出来就是
   「图片之间的转场」，丢掉场景内部的连续运动**。对 a2v 的映射：AI 世界底章据此列出 2–4 个
   「该材质本来会怎么动」的程序层母题小循环（火光呼吸、灰尘飘、水面波光），叠加在生成帧上。
5. **参考帧（5 分钟）**：每段参考帧＝「转场开始前最后一帧」（`ref/` 已按此取）。喂给
   `gen_world_frames.py` 当构图参考（prompt 写「保持参考图构图与物品位置，只改 X」），
   或给三方向小样当基准帧。

## 数字怎么进 a2v 的产物

- **转场节奏表** → `research/beat-sheet.json`：章界拍号、hero moment 落位、结尾定帧时长的量化
  对标（合同的三条秒级判据有了参照系）。
- **运动热图** → 每镜 `action` 的「什么在动」清单；分镜审查时「这一镜的动是抄了热图还是凭感觉」
  有据可查。
- **参考帧** → `research/` 留档 + 生成登记的 reference 输入。
- **拆解记录** → `research/creative-brief.md` 参考案例节：时间段、可借方法、证据等级
  （= 本工具产物路径）。P2 的「采用/弃用」显式决定逐条落在这里。

## 坑（移植时一并收进）

- 参考帧取「转场开始前最后一帧」，不是你觉得好看的那帧——取早了会把上一段转场的余波
  （碎石、光斑）当成画面内容（huashu 埃及段第一版踩过）。
- 网格拟合用「80% 内点下的最大步长」：最小残差法会挑一个小步长硬凑所有点，把噪声当成节拍。
- 全模态模型「听」音轨只当候选：乐器判断可信，BPM、动机音数、音效时间点都要起音检测回校
  （huashu 实测模型报 120、实为 128）。
- 阈值不合适先看 `diff.npy` 的分布再调参，不硬套默认值。
