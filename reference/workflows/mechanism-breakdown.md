# 原理拆解

把部件、连接与变化画出来，说明系统为何这样运转。

本页是整片路线，接在 [统一生产流程](../production-workflow.md) 的对应阶段；授权、工程和终检仍只按 [统一生产契约](../production-contract.md)。不重复询问已确定的风格、文案、画幅与音乐，不新设审批门。

## 输入

- 部件清单、连接关系、状态或物理模型
- 隐喻与真实机制的逐项对应及边界

## 独立工序与产物

1. **画清结构**：部件→功能→连接→观测量的映射。
2. **打样因果闭环**：输入改变→内部传递→读数变化的完整动作。
3. **组织拆装与运行**：总览→拆解→运行→故障或边界的分镜。

## 从零件到可观察因果

机械隐喻先写一张映射表：真实概念、画面零件、输入、状态、读数、隐喻失效的边界。一个变量驱动实体位移和数字表盘，不要分别写两个看似同步的动画。先打样“输入变了，输出为何改变”，再做爆炸图与回装。

`isometric-anatomy` 已有组件但缺随包样片，不把 SPEC 或类型检查当成实渲证明。`WordRelayGeometry` 是已有文字关系镜头，可用于引出关系，不自动证明机械原理。没有足够物理结构时，简洁的数据流图通常更诚实。

真实点云与测绘另看 [点云测绘候选](treatments.md#measured-pointcloud)：必须先有数据集、坐标尺度和来源，随机点不能冒充测量。它需要新的导入与测量验证，不是 HUD 换色。

## 专项检查

- 读数与可见位移同源，不分别手填假同步。
- 管路/线头正确连接，拆装顺序无穿插。
- 隐喻不能暗示不存在的物理机制或证据。

## 接回交付

专项观察写回既有 visual / motion / teaching / audio 审查，保留媒体与源码哈希；仍需整片播放、完整听取及既有 QC。路线目录、静帧、类型检查和计划校验均不证明本片已经通过。无实际检查就记录 `not_performed`。
