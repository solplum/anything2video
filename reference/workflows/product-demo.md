# 产品演示

先展示真实任务怎样完成，再组织产品卖点。

本页是整片路线，接在 [统一生产流程](../production-workflow.md) 的对应阶段；授权、工程和终检仍只按 [统一生产契约](../production-contract.md)。不重复询问已确定的风格、文案、画幅与音乐，不新设审批门。

## 输入

- 真实产品界面、可复测步骤或经授权素材
- 卖点对应的行为证据、品牌资产与行动号召

## 独立工序与产物

1. **验证产品任务**：输入→操作→真实结果的证据与素材。
2. **打样核心演示**：一个完整操作与结果，装配卡仅组织信息。
3. **编排卖点顺序**：问题→使用→证明→收束的完整分镜。

## 从镜头卡到整片

已有 `ProductCardProgressiveAssemble` 负责分层组织产品信息，`CardFlockTumble` 负责一次转场。二者都不是新风格，也不自带用户的真实产品行为。先验证一个任务，再决定卡片何时承接证据：操作前是什么 → 用户做什么 → 结果怎样变化 → 这个结果为何有用。

先读 [产品卡](../../gallery/cards/ui-entrance/product-card-progressive-assemble.md) 和 [卡群翻转](../../gallery/cards/transition/card-flock-tumble.md)，再按卡内映射查看已有参考实现。保持品牌、UI 版本、数值和真实结果可核对。无法访问产品时可以交说明性样片，但明确它不是实录或完成的产品验证。

产品镜头需要接力时才叠加 `match-cut-beat-relay`；先检查主体身份、可见面和接触动作，再比较切点。漂亮转场不能替代使用过程。

## 专项检查

- 演示状态与实际产品一致，不生成假 UI 或伪指标。
- 镜头切换保留操作因果，结束时结果可读。
- 装配与翻卡不遮住产品的关键行为。

## 接回交付

专项观察写回既有 visual / motion / teaching / audio 审查，保留媒体与源码哈希；仍需整片播放、完整听取及既有 QC。路线目录、静帧、类型检查和计划校验均不证明本片已经通过。无实际检查就记录 `not_performed`。
