# 角色动画

用目标、阻碍和动作带来变化，让角色真正完成一件事。

本页是整片路线，接在 [统一生产流程](../production-workflow.md) 的对应阶段；授权、工程和终检仍只按 [统一生产契约](../production-contract.md)。不重复询问已确定的风格、文案、画幅与音乐，不新设审批门。

## 输入

- 角色目标、障碍、尝试和可见结果
- 稳定身份与道具；改编故事另备事实边界

## 独立工序与产物

1. **建立因果节拍**：身份设定和可见的前后状态。
2. **先做最难动作**：接触→承重/推动→释放→落定的实渲短片。
3. **接回整片**：story 与 shot.story 按既有合同绑定镜头。

## 先演得清楚，再装饰

沿用 [角色故事合同](../character-story.md) 的 `story` / `shot.story`，不要另造第二套事实或时间线。先做稳定身份设定与最难动作，检查预备、接触、支撑、释放、落定；纯表情或非接触动作按实际需要设计，不硬套五阶段。

角色变形、转身和表情过渡需要实做，不是给现有几何块加一个人名。遮字幕看片时，观众应能说出目标、障碍、尝试和结果；这是动作验证，不要求所有作品必须对白外完全自明。

[选项冒险](treatments.md#choice-adventure) 已接入 `choice-quest` 实验图元，先列状态、规则、选择与后果，再做原创场景和 UI；目录样片为离线共享 SVG 视频与抽帧证据，后续有有界的浏览器/web-renderer检查；标准 CLI、连续主观运动审片与整片 QC 仍未完成。[卡牌对抗](treatments.md#card-conflict) 已接入独立 `card-conflict` 原型：选牌锁定、支付效果、对手接触和物件后果由同一规则驱动，含反事实及第二原创场景；仅支持 16:9，标准 CLI 与最终成片 QC 尚未完成。两者不等于 `pixel-arcade` 的像素外观，也不是 `ProductCardProgressiveAssemble` 换成角色卡。

## 专项检查

- 遮字幕能说明谁想做什么、动作改变了什么。
- 手脚接触、重心、遮挡和道具归属连贯。
- 真实改编区分已证事实与演绎，不能补写未知对白。

## 接回交付

专项观察写回既有 visual / motion / teaching / audio 审查，保留媒体与源码哈希；仍需整片播放、完整听取及既有 QC。路线目录、静帧、类型检查和计划校验均不证明本片已经通过。无实际检查就记录 `not_performed`。
