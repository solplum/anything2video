# 图解讲解

用图形、文字和可观察的过程，把一个知识点讲明白。

本页是整片路线，接在 [统一生产流程](../production-workflow.md) 的对应阶段；授权、工程和终检仍只按 [统一生产契约](../production-contract.md)。不重复询问已确定的风格、文案、画幅与音乐，不新设审批门。

## 输入

- 要解释的问题、受众与前置知识
- 可核实的事实、数据和贯穿示例

## 独立工序与产物

1. **确定解释模型**：把每句关键结论对应到可见状态变化。
2. **先做难点演示**：带真实旁白的因果动作短样片。
3. **串起整段解释**：前提→操作→结果→边界的分镜与实现。

## 从镜头卡到整片

先画“同一个对象发生什么变化”，再挑图元。例如讲队列：同一批任务进入、排队、出队，编号和位置连续；错误示范是每句话换一张写满标题的卡。`anything2explainer` 的 RAG 案例可查解释粒度，历史黑底与旧字号不必照搬。

线路叙事需要先有节点、分支、汇合和事件顺序，再让线路随事件抵达。它不是给 `line-art` 换红色。[线路叙事原型](treatments.md#transit-story) 已提供事件门控、等待和换乘的手动 kit 与五版无声样片；不是 runtime skin，仍须按本片内容与来源重新制作和验收。

优先打样最容易误解的中段，并让没看稿的人复述变化。若回答仅是“文字在飞”，回到模型与动作设计，不靠增加特效修复。

## 专项检查

- 遮掉字幕仍能看出输入、变化和输出。
- 公式、数字、指示线与旁白指向同一对象。
- 阅读时间足够，不能把卡片入场当作全部解释。

## 接回交付

专项观察写回既有 visual / motion / teaching / audio 审查，保留媒体与源码哈希；仍需整片播放、完整听取及既有 QC。路线目录、静帧、类型检查和计划校验均不证明本片已经通过。无实际检查就记录 `not_performed`。
