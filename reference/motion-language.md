# 运动语言词典（导演层）

本文件把运动、物理、光照与声音组织成镜头选择。内容目标与工程规则见 `production-contract.md`、`production-workflow.md`、`directing-playbook.md`；具体组件候选见包内 `explainer/motion-vocabulary.md`。旧样片的颜色、帧数和效果配额仅作其风格参考。

来源索引：观默《用 Codex 自动生成顶尖动效视频》与 xilo《零基础入门 Opus 5.5 做视频，万字拆解+Skill 全开源》，链接见 `opus55-cases.md`。索引中的制作路线属于 `author_claim`，不能凭文章标题或视觉观感认定官方模型流程；下列导演选择由本skill整理。

## 1. 动作有原因与结果

重动作可拆成 **预备 → 加速 → 接触 → 形变 → 过冲 → 回稳 → 次级响应**。先写触发原因和最终状态，再选择需要的阶段。机器按钮、轨道运动、数据流可以使用另一套明确规律；轻量标签不必演一轮碰撞。

| 阶段 | 作用 | 实现与判断 |
|---|---|---|
| 预备 | 预示方向与能量 | 落前微升、投前回收；机械系统可由指示或驱动状态预示。 |
| 加速 | 建立重量与速度 | 连续位置曲线；表达刚体时保持结构，有机/卡通风格才做合适拉伸。 |
| 接触 | 让观众看到因果时刻 | 真实碰撞、选择命中、流程交接；接触位置和后续反馈一致。 |
| 形变 | 显示受力或材质 | 形变量跟随速度/受力，文字和真实产品不做无依据变形。 |
| 过冲 | 表达余能 | 可用受控 `spring()`；不让关键文字反复弹动到无法读清。 |
| 回稳 | 形成可读结果 | 给观众看清终态；静止是合法结果，不必追加idle。 |
| 次级响应 | 环境或配角反馈 | 阴影、波纹、碎屑、数字、声音在原因之后发生。 |

连续运动保持对象身份、方向和动量，避免每段重置位置与弹簧导致跳变。风格选择阶梯或量化运动时，验证其刻意节奏；不要套平滑度探针误判。

## 2. 相位组织注意力

错相适合顺序处理、因果传播与注意转移；同步适合比较、共同触发、齐发和真实并行事件。采用哪一种，分镜写明原因。没有统一的“所有层必须错开”或“相机不能和入场同动”禁令。

一个轻量的 **30fps样例**：主体先动，相关次层晚2–4帧，相机再晚2–3帧，环境反馈与标签跟随实际事件。这不是固定物理定律；换帧率按秒重算，因果顺序和阅读结果比帧数重要。列表错峰可以从每项约0.067秒起步，长列表需确认最后一项仍有阅读时间。

相机移动为查看局部、揭示结构或连续承接服务。HUD和字幕在屏幕空间保持可读；复杂屏需要移动时，先减少同时发生的注意目标。全层共用一条函数仅在意图确实一致时成立。

## 3. 按材质与镜头任务选物理表现

| 表现 | 适用任务 | 需要成立的关系 |
|---|---|---|
| 重力抛物线 | 掉落、投掷 | 起点、方向、落点连续；有碰撞时能量去向可见。 |
| 碰撞连锁 | 传动、触发、级联 | 接触先于响应，延迟符合距离与材质。 |
| 弹跳 | 有弹性物体落地 | 高度随损耗下降，触地压缩与反弹连续。 |
| 滚动惯性 | 球、轮、输送带 | 接触处的速度关系一致，停止有合理减速。 |
| 挤压拉伸 | 卡通、有机或可变形主体 | 沿受力轴改变，尽量保持体积；静止时恢复。 |
| 弹簧 | 有弹性地到达目标 | 调整damping与刚度到可控终态，不随机叠加弹簧。 |
| 软体与折叠 | 纸、布、线、柔性物 | 受力端到固定端的传播、弯曲和遮挡可信。 |
| 水波与旋涡 | 液面、扩散、能量示意 | 相位与半径、方向对应，说明是否为物理仿真或示意。 |
| 粒子 | 可见物质、聚散、环境 | 密度、运动与主体相关；不遮住文字，不代替核心解释。 |
| 路径运动 | 请求、流程、物流 | 保留对象身份；输入、处理、输出对准旁白和标注。 |

夸张参数要由设计稿选定，先小样再整片复用。比如30fps卡通冲击可试0.1–0.2秒预备、1.1–1.2倍拉伸和0.1秒压缩；这些是样例，不是机械图、品牌标识或全部镜头的验收门。

## 4. 光照与空间

有材质和空间时，设计稿声明当前场景的主光方向、光源性质、投影与反射。相同对象、同一连续空间的高光和阴影要跟随位置、相机与光源；换景、时间变化或新增光源可以改变方向，需有可见原因。

纯平图解、纸印刷和UI没有义务加主角辉光。静止物体的受光可以静止，允许停留阅读；动光只在光源、环境或镜头确实变化时使用。把整幅抖动当冲击容易破坏可读性，选择时只作用于合适层，字幕与必要信息稳定。

多层响应按真实传播或风格安排，不机械要求全部晚几帧。查看连续片段时重点找接触不成立、影子滑脱、空间矛盾和焦点被强光夺走的帧窗。

## 5. 声音对准实际事件

先写事件，再选声音：掠过可用whoosh，接触可用impact，确认可用短提示，持续运转可用环境声。音乐、音效、白闪均可为零；不能给每次出现强制加ding。

旁白与演示共享时间轴。以分镜 **1起帧** `F` 标记事件时，其秒数为 `(F - 1) / fps`。音效用 `uv run python scripts/sfx_landmarks.py <文件> --json` 实测onset/peak；希望onset落在事件时，`cue.at = (F - 1) / fps - onset`。希望峰值对齐就减peak。若结果为负，调整事件窗、剪辑起点或音效本身，不静默截掉预备部分。

可选择预备音略早、撞击正拍、碎屑余响略后；任何偏移都需实际试听。记录最终混音的时间位置，换配音、音效或混音后重新核对，波形和事件表不能替代听感。

## 6. 可选拍点网格

启用音乐且要声明卡拍时，在项目根分析：

```bash
uv run python scripts/beat_grid.py public/assets/<slug>/bgm.wav --out script/beat_grid.json --fps <project-fps>
```

`project-fps` 替换为 `project.json` 的真实帧率。音乐未启用或不做卡拍时跳过，本节不增加音乐义务。

当前脚本用频谱通量、自相关和相位扫描估计BPM；`reliable` 是内部峰均值阈值判断，**不是拍点正确的证明**。它假设4/4，可能半速、倍速或错判小节头。先试听并检查关键击点；不可靠或不合节拍时，用旁白、操作和阅读建立节奏，不声称已卡拍。

优先使用 `beats_s/downbeats_s` 秒表，转换到分镜1起帧为 `round(t * fps) + 1`；脚本的 `beats_frame/downbeats_frame` 是0起，不直接写进1起镜头合同。程序编曲即使BPM已知，还需确认起拍相位、剪辑偏移和拍号，不能仅凭BPM填写动作帧。

卡拍镜头写期望事件、目标拍点、允许误差与偏移依据；只检查声明的事件，不要求每拍新动作。查看最终混音和连续画面，不能将原BGM网格直接当作已混音对齐证明。

## 7. 用问题定位缺陷

- 动作是否改变了观众需要理解的状态？只换标题或添加装饰时，回到起始条件、操作和结果。
- 同步/错相是否反映真实关系？比较需要同步，级联需要传播；没有理由的统一函数容易抹掉层次。
- 速度、接触、形变与光照是否一致？连续空间里的矛盾优先修根因。
- 停留是否给阅读、操作或结果服务？合法静止记录目的，无信息的长段改稿或重排，不靠微动掩饰。
- 字幕、来源、长命令和CTA能否在目标设备读完？先减信息或改布局，再调整时间。
- 图标能否稳定渲染？默认用有许可的图标库或明确路径；emoji只有在相应字体、平台渲染和风格均实测后采用。
- 框内是否有有意义的信息或状态？空槽仅在容量、等待、填入等机制明确时成立，不用一排空框假装代码或表格内容。

技术探针只能说明所测项。实际运动、听感和教学判断见三轮审查；没有查看能力的检查标为 `not_performed`。

## 8. 事件锚点与局部修改

需要将到达/揭示对准旁白或已验证拍点，或修改一次停留并顺延后续动作时，见 [cue-choreography.md](cue-choreography.md)。模板 `common/motion/cues.ts` 提供具名依赖、到达点对齐和纯时间进度；Studio 的 CueDemo 是可运行例子。保留实录音乐，不以程序配乐替代。
