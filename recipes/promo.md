# 配方：promo（产品或服务宣传）

给产品或服务做一条“看见问题、看懂操作、看到结果、知道下一步”的宣传片。默认15–60秒，关键词与真实演示共同承担说服；长版通过增加证据扩展。讲原理用 `explainer.md`，讲历史谱系用 `epic.md`，新视觉体系另加 `custom.md`。共同工程要求见 `reference/production-contract.md`。

## 1. 叙事骨架与 beats

骨架：**具体困境 → 产品介入 → 功能演示 → 结果证据 → CTA**。同一请求、文件或对象贯穿操作与结果；“更快、更强”须有可追溯的比较条件。

| 拍 | 观众要看到什么 | 设计要点 |
|---|---|---|
| 钩子 | 一个立即能认出的卡点或反差 | 前3秒内建立问题是短片起步目标；可用状态变化、实际输出或明确画面。文字、glitch、旁白立即开口都不是唯一手段。 |
| 产品介入与卖点 | 谁改变了什么 | 一拍只解决一个问题。显示输入、操作和反馈，避免“主标+空面板”替代功能。 |
| 证明 | 结果能检查，承诺有边界 | 数字带来源和条件；无实测数据就展示真实操作与结果，不编造排行榜、口碑或速度。 |
| CTA | 明确、能执行的一步 | 默认端板留2–4秒供阅读；地址、命令或二维码须在实际手机画面验证，不能只留未标明的占位。 |

讲解需要超过一个卖点的两句话时可以增加演示拍，不靠加速念完。不要按模板要求强行插入三个卖点。

## 2. 视觉系统

从 `reference/brand-assets.md` 提取有来源的品牌资产；无品牌包时用中性底和一个有用途的强调色，模板palette只是候选。代码镜头用共享token管理信息层颜色，实录与生成场景不按像素颜色数计“品牌色超标”。

每拍设计三件事，写进分镜或设计稿：

1. **焦点**：此刻观众先看哪个对象，其余层怎样服务它。可读文字、动作和高亮不能同时争主角。
2. **贯穿对象**：开场的请求或产物怎样经过操作并在结尾返回；每次出现都改变状态，不把重复装饰当叙事。
3. **视觉推进**：困境、操作、结果各是什么明暗、空间或色彩状态，为什么。单色平面风格也可成立，无须机械添加暖点、grain、发光或三层材质。

横屏1280×720样例可从主标64–96px、正文28–36px起步；它们不是其他画幅的硬门。竖屏按统一契约重新布局。常驻品牌帽、品牌条是可选图元；启用时留安全区并校验与字幕、演示主体的压叠。`reference/promo-style-guide.md` 提供具体排版与转场起步值。

`ui.tsx`、`fx.tsx`、`Counter` 等库图元按实际任务选用。计数必须显示有意义的终值，不把计数动画的中间值当可引用统计。Glitch、白闪、甩出、镜头推拉只在表达确有需要时启用，零次使用可以合格。

### 2.5 可选镜头参考

外部镜头卡库或动画样例存在且许可可用时，可借其意图与参数组织。任务书登记借用来源、移植范围和已知坑；按本工程帧号、palette和依赖重新实现并实渲染。不得依赖作者机器的安装路径，也不得从参考成片取帧冒充原创资产。Lottie等外挂先验证真实文件、当前依赖版本和关键帧，不把一次旧失败概括成永久不可用。

## 3. 时长档

下表是能相加的**初稿样例**，实际音频与演示节奏决定最终帧窗。并行或单代理由能力与文件边界决定，时长不由代理数量决定。

| 总长 | 困境 | 产品介入与演示 | 证明 | CTA | 内容预算 |
|---|---|---|---|---|---|
| 15s | 2s | 8s | 3s | 2s | 一个问题、一次操作、一个结果。 |
| 30s | 3s | 17s | 7s | 3s | 一至两个相关功能，证据与末功能可连拍。 |
| **45s（默认起稿）** | 3s | 26s | 12s | 4s | 两个功能，加完整结果核对。 |
| 60s | 3s | 36s | 17s | 4s | 两至三个功能，每个有输入与结果。 |
| 90s扩展 | 3s | 48s | 34s | 5s | 增加适用边界、失败/修复或第二份独立证据，不拉长标题。 |

中文口播可按成片每秒约4–5字先估；阅读、操作和留白会降低密度。逐句配音后重测，差距明显则改稿与证据拍。没有旁白也可以用动作、字幕与声音完成此骨架。

## 4. 字幕策略

默认用短主标与操作标签；抖音等静音观看占比高的场景可开简洁旁白字幕。字幕和演示标签分工：字幕解释目的，指示线与短标签对准操作，避免两个层复读同一句。

主标建议先控制在8个中文字符左右，小注先控制在20字左右；长命令拆步骤或换行并留阅读时间，不能缩成不可读小字。实际预算以原生画幅、字体和设备预览为准。模板 `recipe:'promo'` 默认关闭旁白字幕，需要字幕时显式配置并实测；不能仅在文档写“有字幕”。

双语仅在受众需要时启用。英文可以承担节奏、中文承担释义，但事实和操作名称要一致；两种语言不能争夺同一焦点。

## 5. 素材策略

优先展示可核查的产品状态、原始结果与代码图解。真实录屏、品牌资产、授权图片/B-roll、生成场景均可按镜头使用，取舍依据是信息和质量；所有外来素材逐条登记来源、实际许可、完整sha256和用途。曲库或网站名称不是许可证明。

AI素材按 `reference/ai-frame-sop.md` 登记模型、完整prompt、seed或n/a、参考输入、用途、QC与披露；精确UI、文字、数字、命令与数据结果仍由代码或真实实录承担。禁止把生成素材称为实拍、拿参考片帧拼片、把虚构界面或模拟数据当真实功能证据。

## 6. 音频策略

有旁白时先实测当前可用TTS或导入用户配音，试听短样；不得按宿主名称假设有官方云端通道。`uv run python scripts/tts_build.py` 是模板可用路线之一，当前支持的引擎和时间轴参数以脚本为准。短片若需更早开口，调整 `LEAD`、`CHAPTER_GAP` 后重建并实测；不把某组环境变量当任何稿件都达标的保证。

清洁旁白正本是 `audio_narration.wav`。显式重跑TTS可写入新版正本并更新时间轴；混音只读正本，不删除它、不按mtime回拷、不把 `audio.wav` 再当纯旁白。换音轨后所有声音锚点重新核定。

音乐可无。启用时从用户提供的可用曲、许可明确的素材或程序原创中择优，登记来源和编曲seed；`uv run python scripts/mix_audio.py --bed 0.055` 是旁白密集片的保守起步值，真实听感与响度检测决定是否调整。RMS床不是LUFS验收。当前混音器对语音做平滑约7dB让位，并按总音轨做淡入淡出；不要另加旧的inline混音模板。

动作音效先对应具体动作，再测onset/peak；1起动作帧转秒用 `(frame - 1) / fps`。自定义音效轨需要实际接入混音并验听；只有事件表不算已完成。`--sfx sand` 仅在该风格确有铺沙/扫掠时启用。

## 7. QC：技术硬门与导演判断

| 项目 | 验证方法与范围 |
|---|---|
| 工程合同与实渲染 | 类型检查、结构化分镜检查、核对真正注册的镜头、实际视频解码与ffprobe；清单存在不能证明挂载。 |
| 事实与证明 | 逐项对照数字、功能、口碑、许可和原始证据；模拟内容显式标注，未经测量的绝对承诺阻塞交付。 |
| 字幕与CTA | 原生画幅查看开场、复杂中段、结尾的连续片段；检查同屏层、长命令、链接与二维码。 |
| 声音 | 实际试听旁白与最终混音，检查中末段音画对位、刺耳音、音乐抢声与截尾；波形不证明自然度。 |
| 视觉说服力 | 能否从画面看到“产品做了什么、结果是什么”；每拍焦点与贯穿对象的作用，弱中段是否仅剩面板和口号。 |
| 修复回归 | 挑最弱镜头先修，复看原问题帧窗及邻接镜头，最后看完整成片。 |

按统一契约三轮验收。每项写实际工具、片段和 `passed/failed/not_performed`；静态抽帧不签署完整运动审片。材质、glitch、颜色数量、运镜次数是设计选择，不独立作为通过证明。

## 8. 审定点

内容目标时确定受众、平台、时长、证据、品牌与CTA；用户已有授权则主控记录决定。配音前按契约 [文案确认门](../reference/production-contract.md#script-approval) 取得全文确认或明确稿件级授权，泛化自主授权不豁免；先试声音和许可。首轮样片至少覆盖开场、复杂演示和结尾；开场5秒只证明开场方向，不能替代中后段打样。需要方案比较时只改一组有意义的视觉变量，挑选后继续全片。
