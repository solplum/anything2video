# custom：自定义视觉路由

沙画、粉笔、剪纸、水墨、像素等视觉语言需要专门图元时，叠加本路由。叙事仍选择 `explainer`、`promo` 或 `epic`；`custom` 不是 `config.recipe` 枚举。风格服务解释或情感目标，不能仅把常规面板换材质称为定制。

## 1. 图纸先行

新视觉体系在扩建镜头前先完成可渲染的最小图元库。设计稿记录：色板、字体、线条与质感参数、主体构造、原生画幅安全区、贯穿对象、明暗变体、可复用运动规则。共享图元放 `src/` 的独立模块，不把全部体系塞进每个镜头。

先验证一张代表构图和一张复杂构图，再看连续运动：动作前状态、实际动作、停留与离场。类型检查和样张通过只能进入运动打样，不能直接签署成片。已有自主授权由主控审定并记理由；用户有明确视觉偏好时优先遵循。

## 1.5 同风格复用

`styles/` 内已有资产时，先读 `styles/README.md` 与对应SPEC；不要写死“只支持四种风格”。复制所需图元与纹理后调整 `staticFile` 路径、slug、实际画幅和文字语言，渲样张与正本对照色板、质感、版式。样张回归用于防漂移，不能证明新片运动成立。

工程中的临时适配留工程；有验证证据的通用升级才回写风格正本，同时更新SPEC与style-ledger。字体、图标、纹理各自登记许可与署名，不把代码许可自动扩展到媒体。

## 2. 叙事骨架与 beats

继承所选基础配方的信息骨架，重新用本风格定义动作。沙画可以通过铺、勾、填、抹呈现因果；粉笔可以通过推导、擦除、改写表现修正；纸拼贴可以通过移动、覆盖、连接呈现证据关系。不是每镜都重复“纹理底+大字入场”。

每镜记录 purpose、action 和结果。贯穿对象必须在机制里做事；章界可以呼吸，信息阅读可以静止，质感微动只在风格需要时使用。

## 3. 视觉系统

- **形体辨识**：具象主体先用可用的开源图标、真实结构资料或经过审核的资产建立骨架；核对许可，CC-BY保留作者与链接。独有主体可自绘，但先验证比例、拓扑与辨识，不凭未审的复杂path直接扩建全片。
- **质感分层**：纹理优先用预计算资产或共享后处理；元素级逐帧重光栅化先测成本再扩用。grain、发光、暗角不是每种风格的必需层。
- **运动**：形变、笔触揭示与离场以实际运动样片定值。硬切可以保留连续主体，淡出可以归零；不存在所有风格统一的“每帧6.7%淡出”。
- **版式**：1280×720的沙画或双语坐标只作样例；目标画幅独立布局，正文和字幕必须在实际预览可读。风格不能作为缩小关键文字的理由。
- **性能**：同机热渲记录复杂镜头的平均、峰值和测试范围。硬件与内容不同，不以固定500ms定义所有项目质量；渲染不稳或成本超预算仍须定位并修复。

## 4. 时长档

沿基础配方控制内容。换语言后重建真实音频、字幕、全局帧窗及共享覆盖层锚点；英文不固定按中文时长乘1.25。时间轴、Composition、project.json和分镜需要对账。不得把上一片的八幕帧号当新片的固定结构。

## 5. 字幕策略

`config.subs` 可明确设置单语、双语或无字幕；模板字段以实际代码为准。无字幕须能通过画面和受众语言完成信息任务。双语按句或块对位，翻译分段与中文分段共同设计；TTS生成了对照行不代表两行在任意画幅都合适。

给中文和英文独立字号、宽度与安全区，并实际查看复杂同屏镜头。对照行不能挤进底部平台按钮区，长术语拆行或改文案。

## 6. 素材策略

所有基础配方均可按镜头采用代码、真实实录、授权素材与AI素材。风格本体的可控部分由代码图元负责；有机质感、复杂人体或照片级场景需要素材时，先说明叙事用途并做兼容样片，不能通过禁止所有素材压低效果上限。

逐条登记完整sha256、来源、实际许可、作者与用途；AI追加模型、完整prompt、seed或n/a、参考输入、QC与披露，见 `reference/ai-frame-sop.md`。禁止把生成素材当实拍或真实产品证据，也禁止拿参考片抽帧入成片。

## 7. 音频策略

有旁白时先实测可用引擎和样音。用户已授权代决策时主控试听择优；只有候选文件或波形不能声称“已听过”。无旁白按基础配方的声音设计执行。

`audio_narration.wav` 是清洁正本，显式配音更新时换新版，混音不修改或删除正本。`uv run python scripts/mix_audio.py --bed 0.055` 是旁白密集片起步；音乐可无。沙画等有物理质感的动作可显式启用 `--sfx sand`，其他风格默认不注入沙音。床电平不等于LUFS，整轨听感与实测需分别记录。

## 8. QC：技术硬门与风格判断

| 验证 | 方法 |
|---|---|
| 基础工程 | 按基础配方与统一契约验证分镜、挂载、类型、素材、音画、解码与规格。 |
| 形体与风格 | 放大主体，核对来源结构及图纸；检视至少一段复杂中段、开场和结尾的真实运动。 |
| 教学或叙事作用 | 说明风格动作怎样承载信息或情感；只有纹理和装饰循环视为待修镜头。 |
| 双语与常驻层 | 查看真实字幕窗口、内容bbox与覆盖层；验证中末段对位、遮挡和阅读停留。 |
| 质感与性能 | 查看纹理抖动、图标误形、混合边缘、色带，记录同机测试范围及成本。 |

每项记录实际工具、文件/片段、帧窗和 `passed/failed/not_performed`。独立观众的辨识试验有实际参与者才记录；不能凭代理猜测写“3秒内辨认通过”。

## 9. 审定点

稿件或章表仅按契约 [文案确认门](../reference/production-contract.md#script-approval) 执行；新风格追加图纸、样张与真实运动样片。声音可有候选，但不用固定3–4个样音增加无益往返。已有对应授权由主控按节点决定；稿件须明确的稿件级授权，泛化自主授权不豁免。重要偏离记入设计稿与BUILD_NOTES。

## 10. 构建边界

共享图元、工具与覆盖层由主控维护；执行代理只改明确分配的镜头目录。新视觉体系建立前不并行扩建；图纸稳定后独立镜头可并行或顺序，质量门一致。派单模板见 `reference/workflow-orchestration.md`。

## 11. 外部视觉参考

可用已核实的手绘、纸拼贴、音乐视频等参考学习媒介语言、动作组织和对比打样。登记真实链接与观察范围，不把星数快照写成长期质量结论。媒体来源、生成通道与脚本许可分别审核；借设计原则后按本工程合同重新构建。

## 12. 人物混合镜头

人体动作或表情对镜头成立有必要时，可用视频模型人物片段与代码合成。费用与披露按已有授权执行，生成能力先实测。

1. 明确人物身份授权、动作、机位、目标画幅、背景与时长。绿幕只是候选方案；低饱和背景、分割蒙版或原场景合成按真实边缘质量选。
2. 多镜头人物一致性依赖可用参考图、身份约束、模型能力及逐镜审核；同prompt或同seed只能帮助控制变量，不能保证相同人物。
3. 抠像参数通过放大边缘和真实片段确定，核对发丝、半透明物、绿溢、接触影和画面裁切；失败时重生成、重抠或重构，不能仅淡入掩盖缺陷。
4. 素材静音合成时检查主光、视线、机位和运动承接；人物原音若需保留要有声音授权和明确混音。`OffthreadVideo` 数量按实际解码成本测试，不把单层规则当任何机器的保证。
5. 入库并登记来源、模型、完整prompt、seed/参考、完整sha256、镜头用途、QC与披露；代码侧仍负责精确信息、全局节拍和最终确定性合成。

生成片段不是整片验收替代物。素材审核、合成运动、音轨和成片分别签收，未执行的审片项目明确留 `not_performed`。
