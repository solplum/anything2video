# 配方契约

配方说明“这类片怎样讲、怎样看、怎样验收”。工程、音频、素材与证据的共同要求只维护在 `reference/production-contract.md`；生产顺序见 `reference/production-workflow.md`，派单见 `reference/workflow-orchestration.md`。配方不复制另一套运行管线。

> **套餐口径（v3.5.0 起）**：配方（本文档族）管**结构与叙事**——覆盖层集合、验收侧重，随套餐卡的类型而定（宣传→promo、讲解→explainer、史诗→epic；documentary 是档案制作路线，运行时按其接线说明选现有基础配方）。**视觉一律由套餐卡的风格侧决定**：风格元数据以 [catalog](../styles/catalog.json) 为准；仅 `runtimeSkin: true` 的 ID 可填 `config.style`，浅合并覆写 palette/chrome，其余按 SPEC 接 kit。各配方文档中残留的历史视觉描述（黑底MG/深空青/暖纸白等）是 v3.2 前类型绑脸时期的参考，不再构成配方的视觉约束；选型规则与判例见 `reference/style-ledger.md`。

## 0. 类型与接线

- `recipes/explainer.md`、`promo.md`、`epic.md` 是叙事配方；工程 `project.json.recipe` 与 `src/config.ts` 中的基础配方须一致。
- `recipes/custom.md` 是视觉路由，叠加在适合内容的基础配方上；它不是模板的 `recipe` 枚举。不得为关掉字幕而把教学片假设成宣传片，应明确设置字幕与覆盖层。
- 新叙事配方若需要新枚举，必须同时实现配置类型、调色板、覆盖层选择及验证；新增一个 Markdown 文件不会自动完成接线。
- 一个配方一份文件，共享知识放 `reference/`。规范引用须随包可达，禁止依赖作者机器的绝对路径。可引用 `reference/explainer/` 的随包快照，并说明借用范围。
- `template/` 中的 1280×720@30 是起始样例。实际宽、高、fps 从 `project.json` 取；竖屏重新布局并验证手机可读性，不能把横屏坐标乘比例当原生竖屏完成。

## 1. 必备内容

九类内容需要明确，可按叙事特点组织章节；不要求用固定章节数量或机械填表增加重复。

| 内容 | 应写清楚 |
|---|---|
| 定位 | 输入、成片目标、受众、何时改用另一配方。 |
| 骨架与 beats | 每拍让观众看到的状态、动作、结果与证据；时长只是初稿预算，最终按音频和真实动作定帧。 |
| 视觉系统 | 色源、字体层级、焦点、版式、安全区、贯穿对象、风格图元；具体值在工程设计稿中落定。 |
| 时长档 | 一组能相加得到总时长的样例；长版增加演示和证据，不把短版的句数上限强套到长版。 |
| 字幕 | 是否启用、语言、文本预算、阅读停留、同屏分工；无字幕要有受众和发布场景理由。 |
| 素材 | 代码、产品实录、授权素材、AI素材各自承担什么；逐条来源、许可、完整哈希、用途及AI登记。 |
| 音频 | 有无旁白与音乐、真实可用的引擎、清洁正本、时间轴、混音、听感与实测规格。 |
| 验收 | 区分技术硬门与导演判断；每项说明实际检查方法和所覆盖范围。 |
| 审定点 | 稿件按契约文案门；声音、风格样张、运动样片及素材路线记录实际决定者和时机，沿用对应授权。 |

## 2. 数字与判据

数字需要来源与适用范围。不要为了“可执行”把一次样片的字号、镜头数、材质层数、运镜次数写成所有片子的硬门。

- 工程必填数字：实际画幅、fps、totalFrames、镜头帧窗、字幕与音轨时间窗。
- 项目设计数字：字号、位置、停留时间、运动范围、音乐床等，由真实画幅与样片确定后写进分镜及设计稿。
- 导演建议数字：可以给起步范围，说明如何通过真实片段修订。静止、平面设计、无BGM不因偏离样例自动失败。
- 样例以30fps解释时必须标“样例”；实际秒转帧用工程fps。分镜1起含端点，Remotion0起；`Sequence.from = shot.from - 1`，`duration = shot.to - shot.from + 1`。
- 差异超过目标时长时先修内容和动作预算，再重建时间轴；不要统一加速旁白或拉长静态章凑数。

## 3. 共同审定点

1. 内容目标：受众、平台、语言、目标时长、要学会或相信的一件事、事实资料与品牌约束。
2. 稿件或章表：按 [文案确认门](../reference/production-contract.md#script-approval) 在配音前取得确认或明确稿件级授权，改稿按哈希重新对账并重建时间轴。
3. 声音与素材路线：样音、许可、生成能力及费用已有授权则直接执行；声音质量仍需实际试听。
4. 视觉与运动样片：看开场、复杂中段和结尾；新风格先验样张，再验运动。

用户已有对应授权时，主控按上述节点记录决定，不重复停等；稿件豁免仅限明确的稿件级授权，泛化自主授权不覆盖。关键事实、素材使用权或发布授权确实缺失时，仅补问缺失项。

## 4. 验收状态

每项只能记录 `passed`、`failed` 或 `not_performed`，并附实际工具、文件或片段、帧窗和发现。`not_performed` 不能改写成“通过”。探针、联系表、类型检查和打包各证明各自范围，不证明整片运动、听感或教学成立。

技术硬门包括工程合同、真实挂载、可解码、规格一致、事实与素材登记完整。导演轮判断解释是否成立、焦点与动作是否清楚、素材是否可信、声音是否合格。阻塞问题未解决时保留工程与诊断，交付状态明确为未验收，继续修复；不能自动把目标改成更短或更低质量的成片。
