# 配方：epic（史诗品牌片）

给确有历史、技术源流或社区传承的主题，制作“谱系蒙太奇+做事的贯穿符号”的品牌片。观众最终要读出一条传承关系。卖功能用 `promo.md`，解释机制用 `explainer.md`。方法见 `reference/epic-brand-film.md`，工程要求见 `reference/production-contract.md`。

> **能力前置**：本配方世界层默认依赖 AI 生图。开工先跑 `node <skill>/scripts/doctor.mjs` 看 `imageChannel`——可用则 `gen_world_frames.py --generate` 直出候选；不可用时世界层降级为程序材质（`reference/materials.md`）或手工生成+`--register`，分镜**禁止排布依赖生成的 AI 镜头**，别等生成步才撞墙。三条合法通道：API 环境变量三件套、宿主实测图像生成（登记同 `ai-frame-sop.md`）、手工生成素材；三者皆无就选程序材质路线。

## 1. 叙事骨架与 beats

骨架：**起源状态 → 传承与转变 → 当下回应 → 收口**。章数按资料与叙事决定；一章完成一个主题，不固定8–16章。

| 段 | 画面与符号任务 | 时长如何定 |
|---|---|---|
| 开场 | 建立一个世界和问题，符号第一次采取行动 | 让场景、动作与阅读都有时间；可短促也可缓起，由样片判断，不设8秒硬下限。 |
| 谱系章 | 换时代、媒介或任务，但保持可说明的传承关系 | 章长可不同，重要转折多给时间，重复信息短切；不能以章数充实长度。 |
| 当下 | 前面的线索在当下产品、人物或社区产生具体回应 | 展示回应的动作，不仅切到logo。 |
| 收口 | 家谱、首尾同景或贯穿对象回归，完成前面的关系 | 结论与EndCard留实际阅读时间；日期、品牌和来源可核查。 |

历史跨度越大越需定位。年代角标或时间轴至少能让观众知道“什么时候、在哪里、它和前一章什么关系”；无史实依据的连接写为比喻，不写成真实技术继承。

## 2. 视觉系统

**世界层**承担媒介、空间与材质；**信息层**承担精确文字、数字、图解、角标与品牌符号。世界可由程序、授权资产或AI生成；精确信息由代码或可核实实录负责，不把生成铭文当历史资料。

每章记录色温/明暗、材质、镜头任务、主光和符号作用，整片建立有理由的视觉推进。平面信息章和世界章可以交替；不能因为有家谱或代码图示就判“质感不足”。信息层颜色由共享token管理，与世界背景实测对比。

模板 `overlay/epic/` 的 EpochBadge、PoemSubtitle、EpicEndCard 及 `TreeGrow`、`ParticleText`、`TempGrade` 是可用图元，不是必须全部出现。模板1280×720上的角标左缘、字幕带与字号是横屏起步值；原生竖屏或不同画幅重新布局并查看实际平台预览。

贯穿符号每次出现都要改变状态：照亮、印记、连接、传递、定位或成为结果。持续角标不能承担全部贯穿；章间暂时缺席可以有叙事理由，不能用“每章均可见”代替行动设计。

## 3. 时长档与章表

默认先起120秒草案；短版或长版均按真实资料扩缩，不固定每章8–14秒。下表只说明内部可加总：

| 总长样例 | 开场 | 谱系与转变 | 当下 | 收口 |
|---|---|---|---|---|
| 60s | 6s | 35s | 12s | 7s |
| **120s** | 10s | 78s | 20s | 12s |
| 180s | 12s | 120s | 32s | 16s |

时间轴选择明确主锚：叙事章表、音乐结构或真实旁白。音乐主导时先审曲再按乐句组织章；叙事主导时配乐适应章表。听不到明确拍点的ambient曲不声明重拍精度。音乐不能逼历史内容歪曲或让阅读窗口不足。

默认可无旁白；需要关键解释可加入旁白并走清洁音频流程。无旁白章表样例：

```json
[
  {
    "title": "从手工到记号",
    "era": "示例年代",
    "place": "示例场景",
    "seconds": 8,
    "lines": [{"zh": "先留下一个记号。", "en": "A mark remains.", "at": 1, "dur": 4}]
  }
]
```

无旁白可用 `uv run python scripts/chapter_timeline.py`，从 project.json 读取 slug/fps，保留 material 等章元数据并更新 totalFrames。仅音乐确为主锚时传 --bgm；--fit-bgm 同比例缩放章长及字幕 at/dur，仍须重查阅读、动作和章界。已有 audio.wav 默认保留，显式 --force 才换成静音床。其他音频脚本和组件的fps需单独核对，不能改声明后沿用旧帧号。

## 4. 字幕策略

短句是点睛与连接，必要信息不能因追求诗意被删掉。默认单语，受众确需双语再启用主行与对照行；两行意思一致，不要求逐字对译。年代、人物、产品名和结论必须与事实来源一致。

字幕数量与停留由阅读和动作决定。章内可以有纯画面呼吸；一章4句以上不自动失败，但连续字幕淹没世界时需改稿。示例可从中文每行约12–20字、英文每行约40–48字符起步，最终依据原生画幅验读。

使用模板诗行层时 `config.subs:'none'` 只关闭普通旁白字幕，诗行仍来自实际subs数据；有旁白时明确两套文本角色，避免重复或丢失。逐字入场可用，但要留完整可读态，不把逐字动画吃掉阅读时间。

## 5. 素材策略

按章选择真实适用世界，不用历史器物填满软件教程。生成静帧、短片、授权素材与程序材质都可用，AI不是epic专享权限。细则见 `reference/ai-frame-sop.md`。

静帧推拉、裁切与分层视差只在能承载动作时使用；需要真实有机运动可生成视频并核对连续性。运镜范围、片段长度和解码成本经实际样片确定，不固定全片只能四段视频或推到1.12倍。

`uv run python scripts/gen_world_frames.py --generate-prompts` 保留显式 material，并从 project.json 派生 slug 与画幅；未知材质拒绝，不回退洞穴。--generate 需实测且授权通道，候选按 --take 区分，已有文件默认保护。生成的 MANIFEST.json 保存完整哈希和实际提交prompt，qc 三项为 not_performed，许可仍待真实核查。服务可用尺寸未必等于项目比例，核对源分辨率和实际裁切再审。手工 --register 必须提供 --source/--license/--model/--prompt/--seed/--disclosure。合格资产审核后纳入 storyboard.assets，不能自动标通过。

参考片只借叙事、材质语言和镜头关系，不取帧入成片。参考视频来源、是否官方、模型名称和生成比例没有原始证据时保留为未核实，不通过视觉观感宣布确认。

## 6. 音频策略

音乐和环境音可以主导，也可以无音乐。音乐来源与许可逐条核对；程序编曲登记源码、参数与seed，AI音乐登记生成信息和许可。程序编曲现成工具 = `scripts/bgm_generate.py`（底层 `audio-engine/mgaudio`，国潮/ambient 等配方含合成筝笛，依赖集见 `audio-engine/VENDOR.md`；登记行直接用其 stdout，圈选纪律见 `reference/bgm-bakeoff.md` 程序编曲通道节）。前后呼吸、转章能量和结尾淡出以实际整轨试听判断。

无旁白时用 `uv run python scripts/mix_audio.py --epic --bed 0.12` 是模板起步路线；床电平不是响度达标证明，最终媒体需要响度、peak、时长与听感分别验证。章表生成的静音床只是占位，不能把占位音轨叫“音乐混音完成”。

有旁白时使用 `audio_narration.wav` 正本和常规混音；不使用 `--epic` 绕过旁白。换章长或音乐后同步重建时间轴、覆盖层锚点和最终混音，再核对全部关键转场。声明精确卡拍的镜头才按当前beat_grid和实际声音落点测偏差。

## 7. QC：硬门与叙事判断

| 验证 | 证据 |
|---|---|
| 工程与全片规格 | 类型检查、分镜合同、镜头真实挂载、完整解码、实际ffprobe；各章窗与totalFrames连续对账。 |
| 史实与谱系 | 年代、地点、人物、产品与传承关系逐项来源；比喻显式区分事实。 |
| 材料可信度 | AI/授权资产许可、完整sha256、prompt/seed/用途/QC/披露；生成画面放大三查且视频查连续伪影。 |
| 信息层 | 实际片段检查年代定位、字幕阅读、焦点与平台安全区，不仅静态坐标。 |
| 贯穿与收口 | 逐章指出符号做了什么及其结果；完整看片确认最后一拍回应开场关系。 |
| 声音与时间 | 整轨试听；无旁白音轨总长对totalFrames，有旁白另核对中末段字幕；音乐卡点仅检查已声明镜头。 |
| 修复回归 | 最弱章、复杂中段、结尾和组界真实片段重看；源或音轨变化后旧审片不能沿用。 |

传统blank、subject、liveness、material探针是提示工具，先声明ROI、合法静止与背景特征。源码出现 `Footage` 或 `TreeGrow` 不证明画面丰满；静态家谱也不因“不动”自动失败。所有审片写工具、实际范围和 `passed/failed/not_performed`，不能用contact sheet称完整动态审片通过。

## 8. 审定点

内容目标时确定历史跨度、受众、平台、时长、事实证据与素材路线；章表、诗行及有旁白的稿件按 [文案确认门](../reference/production-contract.md#script-approval) 定稿，泛化自主授权不豁免稿件确认。首轮验一个开场世界、一段复杂中段与收口；批量生成前先验证风格、符号和信息层兼容。用户已授权自主决策则主控记录并执行，不逐章停问。预算充足仍要每轮依据具体缺陷修复，不能随机重生成，也不能达到轮次后自动降成更低质量交付。
