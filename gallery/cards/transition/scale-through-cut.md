name: scale-through-cut
一句话: 缩放穿越切——出画物体越缩越快钉在锚点上切走，入画同主体换了个"世界"从 1.8x 继续缩回 1，缩放速度跨切点连续，一次 pull-back 贯穿两个世界
适用: 换媒介/换世界的接缝：3D 渲染→平面图、设备→纯 UI、品牌卡→产品场景、章节点题后的英雄回拉
时长: 出画 8–12f + 入画 15–20f（@30fps；动作跨切点总占约 0.8–1.1s）
能量: 高（签名级，一支片 ≤2 次）
标签: transition
来源: 手法研究自 cinetic (MIT, Leonxlnx)；配方说明独立整理，尚无本仓实现/演示

## 意图
shot-transitions 六式管"怎么把剪刀藏起来"，本卡管"剪刀剪完观众还觉得
是同一条运动"：切点两侧的对数缩放速度 `d ln(k) / dt` 连续（时间单位为秒），观众读到的不是"切了"而是"拉镜头拉过了世界的边界"。与
transition-travel（同表面横移）分工：那卡走位移，本卡走缩放。

## 动效核心
- 定一个锚点屏坐标，出/入两物体都钉在锚点 ±30px 内（transform-origin
  或相机 Shot 的 sx/sy 固定）
- 出画：k 1→0.75–0.8 可先试 8–12f ease-in，再从实际曲线量出切点的对数速度；在指定事件点硬切，不把旧 @60fps 的 −7%~−9% 每帧值直接当成 @30fps 指标
- 入画：同主体换新媒介，可从 k=1.8 收至 1.0；根据出画的对数速度设置起始导数并收至零速度。15–20f 仅作起点，不能仅凭两段 ease 名称保证速度连续；锚点、内容尺度与阅读仍须审片
- 宏观变体：入画直接从 S0=8–9 的满屏微距开始，每帧几何收敛
  收敛的是余量 `k−1`：`k(f)=1+(S0−1)×0.84^(2f)`（@30fps，逐帧余量乘 0.7056≈0.71）；|1−k|<0.01 时吸附到 1，S0=8–9 时首个达标整帧为 19–20f，而非 15f
- 推近变体（反向）：英雄在末 8–12f 隆起 1→1.22 且全帧压暗
  （brightness 1→0.6），切后从 0.8 涨回 1 共 15f
- Remotion 要点：整段缩放只写在一个 wrapper transform 上（禁动
  left/top），切点两侧按同一秒制对数速度约束构造、采样并检查曲线；急缩段包
  CameraMotionBlur，慢收段保持锐利

## 参数表
| 参数 | 典型值 | 调节手感 |
|------|--------|----------|
| 出画时长 | 10f ease-in（8–12f） | >14f 读作普通缩小，冲击感消失 |
| 出画终点 k | 0.75–0.80 起试 | 改变终点或时长后重算速度衔接，不能只看比例端点 |
| 入画起点 k | 1.7–2.0 | 配合锚点，入画首帧必须比出画末帧"更大" |
| 入画时长 | 15–20f 起试，按速度约束调整 | 起始对数速度衔接出画，结束速度为零；每帧百分比依 fps 改变 |
| 锚点漂移 | ≤30px | 两物体中心差超 30px 读作跳切 |
| 使用频次 | 全片 ≤2 次 | 签名级手法，第二次出现必须隔一整幕 |

## 已知坑
- 两侧物体必须能共享同一屏锚点；做不到就换 anchor-overlay-cut
- 两侧都是静场时禁用——没有速度可续，硬凑读作缩放跳切
- 入画侧文字要在缩放中保持可读：先按目标尺寸排版再整体 scale，
  禁止在 perspective 下直接放大排版文字（会栅格化发虚）
- 切点可对齐已核实的音乐/语义事件；无声版仍按几何、锚点和速度连续性核对，卡点本身不保证接缝成立
- 上游 @60fps 的每帧速度不能沿用到 @30fps。这里仅更正换算与验证方法，a2v 未建 demo，未认证动态接缝

## 换算算例（未接入渲染）

<!-- audit-example:scale -->
```js
const ratioAtFps = (ratio, sourceFps, targetFps) => {
  if (!Number.isFinite(ratio) || ratio <= 0 || !Number.isFinite(sourceFps) || sourceFps <= 0 || !Number.isFinite(targetFps) || targetFps <= 0) throw new RangeError("invalid scale ratio");
  return ratio ** (sourceFps / targetFps);
};
const macroScale = (frame, fps, startScale) => 1 + (startScale - 1) * 0.84 ** (60 * frame / fps);
```

恒定局部对数速度下，@60fps 的 r=0.93–0.91 对应 @30fps 的 r²=0.8649–0.8281（每帧缩 13.51%–17.19%），不是原百分比不变。这只是单位换算示例，不是推荐速度。变速段应重采样实际曲线，以 `fps × ln(k_next/k_prev)` 估计速度并在切点验证导数；相邻有限帧的平均速度不必严格相等。
